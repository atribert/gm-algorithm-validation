# SM3 摘要算法实验记录

## 1. 实验目标

本实验不从零实现 SM3，而是调用 OpenSSL 提供的 SM3 实现，建立一个可重复运行的算法验证流程：

```text
JSON 测试向量 -> 输入校验 -> OpenSSL SM3 -> 比较预期摘要 -> PASS/FAIL
```

实验目标包括：

1. 验证本机 OpenSSL 能够正确计算 SM3。
2. 使用标准测试向量验证算法输出。
3. 检查执行器能否拒绝错误的测试向量格式。
4. 检查预期摘要错误时能否正确报告失败。
5. 通过文件修改实验观察哈希函数对输入变化的敏感性。

## 2. 实验环境

本次实验环境为 Windows PowerShell，使用 Python 编写测试向量执行器，实际密码运算由 OpenSSL 完成。

```text
OpenSSL 1.1.1i  8 Dec 2020
Python 3
```

OpenSSL 已确认支持 `SM3`。当前仓库没有安装或调用独立的 GmSSL，也没有从零实现 SM3 压缩函数。

## 3. 实验文件

| 文件 | 作用 |
|---|---|
| `runner.py` | 读取、校验并执行 SM3 JSON 测试向量 |
| `vectors/sm3.json` | 保存标准测试向量及来源信息 |
| `tests/test_sm3.py` | 测试执行器和 OpenSSL SM3 输出 |
| `examples/message.txt` | 文件摘要及输入修改实验 |

## 4. 测试向量执行流程

执行命令：

```powershell
python runner.py vectors\sm3.json
```

执行器进行以下操作：

1. 以 UTF-8 读取 JSON。
2. 确认算法名称为 `SM3`。
3. 检查测试组和测试用例结构。
4. 检查 `tcId` 是否为唯一整数。
5. 检查 `msg` 和 `md` 是否为合法的完整字节十六进制字符串。
6. 检查 `msgLen` 是否等于 `msg` 的实际 bit 长度。
7. 将 `msg` 解码成原始字节，通过标准输入传递给 OpenSSL。
8. 调用 `openssl dgst -sm3 -binary` 获得 32 字节摘要。
9. 将实际摘要与预期摘要比较并输出结果。

使用标准输入和二进制输出可以避免 PowerShell 管道附加换行、文本编码转换或 OpenSSL 文本输出格式影响验证结果。

## 5. 正式向量结果

当前 `vectors/sm3.json` 包含 31 个测试向量（原 15 个用例如下，新编号 16—31 见本节补充）：

| tcId | 消息 | 来源类型 | 测试目的 |
|---:|---|---|---|
| 1 | `abc` | `standard` | 验证基础标准输出 |
| 2 | `abcd` 重复 16 次 | `standard` | 验证 64 byte 标准消息 |
| 3 | 空消息 | `regression` | 验证零长度输入 |
| 4 | 55 byte 全零 | `regression` | 验证单个填充分组边界 |
| 5 | 56 byte 全零 | `regression` | 验证填充增加新分组的边界 |
| 6 | 63 byte 全零 | `regression` | 验证接近完整分组的输入 |
| 7 | 64 byte 全零 | `regression` | 验证一个完整消息分组 |
| 8 | 65 byte 全零 | `regression` | 验证跨分组输入 |
| 9-12 | 1、31、32、33 byte 全零 | `regression` | 验证短消息和 32 byte 摘要长度附近边界 |
| 13-15 | 127、128、129 byte 全零 | `regression` | 验证两个完整消息分组附近边界 |

其中消息 `abc` 的标准测试向量为：

```text
消息文本：abc
消息十六进制：616263
消息长度：24 bit
```

预期摘要：

```text
66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0
```

实际执行结果：

```text
[PASS] tcId=1 ... tcId=31

Total: 31, Passed: 31, Failed: 0
```

两个标准向量来自 `GB/T 32905-2016`。最初 13 个边界摘要由 OpenSSL 1.1.1i 生成，用于版本回归，并已使用 Python gmssl 3.2.2 交叉验证。全部通过说明当前 JSON 解析、边界长度、字节转换和结果比较链路能够正常工作。

## 7. 文件摘要与输入修改实验

示例文件位于 `examples/message.txt`。计算原始文件摘要：

```powershell
openssl dgst -sm3 examples\message.txt
```

当前版本示例文件的实测摘要为：

```text
e80350db1655830b92331fcfbb96802446fd435dfc54e6f95bba552b9390f26d
```

记录输出后，将文件中的一个字符修改，例如把：

```text
SM3 experiment message
```

临时改成：

```text
SM3 experiment Message
```

再次运行相同命令并比较两个摘要。完成比较后恢复原始内容，再次计算摘要。

预期观察：

- 只改变一个字符，SM3 摘要也会显著变化。
- 恢复完全相同的文件字节后，摘要会恢复为原值。
- 文件末尾换行和文本编码也属于输入字节的一部分，因此可能改变摘要。

这里观察到的是哈希函数对输入变化的敏感性。仅凭少量样本不能对雪崩效应作严格统计证明，如需量化，应批量翻转输入 bit 并统计输出 bit 的变化数量。

## 8. 实验结论

本实验完成了一个可复现的 SM3 验证闭环。2 个标准向量和 6 个边界回归向量全部通过，输入校验、失败结果和环境错误路径也经过单元测试。

同时需要注意：

- SM3 输出固定为 256 bit，但摘要不能提供消息机密性。
- 普通 SM3 摘要不能独立证明消息来自某个可信发送方。
- 主动攻击者如果能够同时替换消息和摘要，接收方仍无法发现伪造。
- 需要消息认证时，应使用 HMAC-SM3 等带密钥的认证机制。
- 测试向量通过只能证明所测试输入上的输出一致，不能单独证明整个密码库不存在实现漏洞。
