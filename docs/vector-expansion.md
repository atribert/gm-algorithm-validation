# 测试向量扩充实验（2026-10-18）

本轮将正式回归向量从 **64 个扩充到 160 个**，新增 96 个用例。保留原有编号，不修改算法接口；ACVP 请求样例单独维护，本轮未增加其数量。

| 文件 | 原数量 | 当前数量 | 新增覆盖 |
|---|---:|---:|---|
| `vectors/sm3.json` | 15 | 31 | 填充边界、4096 字节、FF、中文、NUL/高位字节 |
| `vectors/hmac-sm3.json` | 4 | 16 | 非零 63/64/65 字节密钥、空消息、131 字节密钥和 1024 字节消息 |
| `vectors/sm4.json` | 28 | 54 | CTR 47/48/49 字节与计数器进位、零/FF 密钥、另一组 IV、多分组 |
| `vectors/sm4-ctr-hmac-sm3.json` | 6 | 14 | 15/31/32/47/48/49/256 字节和中文的加密、标签及解密回环 |
| `vectors/sm2.json` | 6 | 16 | 不同长度/二进制/中文签名、自定义 ID 有效签名和额外篡改 |
| `vectors/sm2-encryption.json` | 5 | 29 | 三种格式解密、C2/C3 篡改、错误私钥、六个格式转换方向 |

## 为什么增加这些输入

- **SM3 的 119/120/121 字节**：检查第二个分组附近的填充变化。递增数据能补充原来全零消息的覆盖。
- **HMAC 的 63/64/65 字节密钥**：检查 SM3 64 字节分组边界两侧的密钥处理；长密钥需要先哈希。
- **CTR 的计数器进位**：初值低字节为 `FF` 或低两字节为 `FFFF`，处理后续分组时会发生进位，帮助发现计数器方向或进位错误。本轮不测试完整 128 位计数器回绕。
- **SM2 的 1/31/32/33/128 字节**：覆盖短消息和 KDF 的 32 字节边界；128 字节消息还会触发 DER 长长度编码。
- **负向向量**：密码运算拒绝被篡改的数据，才算通过该用例。它们是合法 JSON；非法十六进制、长度等输入错误继续由现有单元测试检查。

## 数据来源与可复现性

新增用例使用 `batch: "boundary-2026-10"` 标记，并在 `source` 中记录后端版本。本机实际验证使用 OpenSSL **3.5.4** 和 Python **gmssl 3.2.2**。它们是本地回归或负向向量，未新增官方标准向量，也不代表正式认证。

SM3、HMAC、SM4 和认证组合的期望值先用 OpenSSL 计算，再用 GmSSL 比较。认证组合的标签覆盖 `GMENC || version || algorithm || IV || 密文长度 || 密文`；生成脚本独立拼接认证字节。SM2 固定签名/密文通过 GmSSL 生成，再由 OpenSSL 实际验签/解密；转换期望值由生成脚本独立编码，包含所有不同格式之间的转换方向。

测试私钥 `d=1`、固定签名随机数 `k=10…17`、固定加密随机数 `k=30…34` 只用于公开测试数据。随机回环用例仍然随机生成密文，不要求每次密文相同。

需要复现新增数据时，在仓库根目录运行：

```powershell
python tools/expand_vectors.py --openssl "C:\Program Files\Git\usr\bin\openssl.exe"
```

脚本先验证全部文件，成功后才写入。再次运行会替换本批次用例，保留其他批次和手写向量；相同后端版本下输出保持一致。请在运行后检查 Git 差异。需要完整支持 SM2 的 OpenSSL 3；本机 PATH 中的旧 OpenSSL 1.1.1i 无法完成全部 SM2 验证。
