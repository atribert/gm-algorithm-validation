# 测试向量及说明

当前 `vectors` 目录共有 **6 个 JSON 文件、160 个测试用例**。向量是“输入 + 预期结果”；正向用例要求输出正确，负向用例要求拒绝错误数据。测试编号 `tcId` 在各文件内唯一，文件间可以重复。

| 文件 | 数量 | 用途 |
|---|---:|---|
| `sm3.json` | 31 | 计算并比较固定 32 字节摘要 |
| `hmac-sm3.json` | 16 | 计算并比较固定 32 字节消息认证标签 |
| `sm4.json` | 54 | ECB、CBC、CTR 加密和解密 |
| `sm4-ctr-hmac-sm3.json` | 14 | 认证加密的密文、标签和解密回环 |
| `sm2.json` | 16 | 有效签名接受、错误签名拒绝 |
| `sm2-encryption.json` | 29 | 固定密文解密、随机回环、篡改拒绝和格式转换 |

## SM3（31 例）

字段：`msg` 为消息十六进制，`msgLen` 为消息的 bit 长度，`md` 为预期摘要。

- **1—2**：`abc` 和 `abcd` 重复 16 次，来自国标 GB/T 32905-2016。
- **3—15**：空消息，以及 1/31/32/33/55/56/63/64/65/127/128/129 字节全零消息。
- **16—25**：54/57/119/120/121/255/256/257/1024/4096 字节递增数据，检查填充和多分组处理。
- **26—31**：FF 字节、中文 UTF-8、内嵌 NUL/高位字节、16/65 字节递增数据，补充内容类型。

## HMAC-SM3（16 例）

字段：`key` 为密钥，`msg` 为消息，`msgLen` 单位为 bit，`tag` 为预期认证标签。

- **1—4**：16 字节示例密钥、1/64/65 字节全零密钥与 `abc`。
- **5—10**：63/64/65 字节非零密钥，分别搭配空消息和 119 字节消息，检查密钥分组边界。
- **11—15**：131 字节长密钥，搭配 55/56/64/65/1024 字节消息，检查长密钥先哈希的路径。
- **16**：1 字节 FF 密钥和中文消息。

## SM4（54 例）

组级字段 `mode` 指定模式，`direction` 指定加密/解密。用例字段为 `key`、`pt`（明文）、`ct`（密文），CBC/CTR 还需要 `iv`。密钥和 IV 均为 16 字节；ECB 不使用 IV。ECB/CBC 使用无填充的非空整分组输入，CTR 使用任意非空整字节输入。

- **1—2**：国标 GB/T 32907-2016 单分组 ECB。
- **3—14**：CBC 实验、ECB 重复块推导、20 字节 CTR 和 ECB/CBC 三分组实验。
- **15—28**：CTR 的 1/15/16/17/31/32/33 字节边界。
- **29—34**：CTR 的 47/48/49 字节边界。
- **35—38**：CTR 低字节 FF、低两字节 FFFF 的跨字节进位。
- **39—46**：ECB/CBC 全零或全 FF 密钥与数据。
- **47—54**：另一组 CBC IV、1024 字节 CTR、256 字节 ECB/CBC。

每对相邻的奇/偶编号（除原来按组安排的情况）分别验证加密和解密；执行时按模式分组输出，编号不一定连续递增。

## SM4-CTR + HMAC-SM3（14 例）

字段：`sm4Key`（16 字节加密密钥）、`hmacKey`（32 字节认证密钥）、`iv`、`pt`、`ct`、`tag`。运行器比较密文、标签和恢复的明文。

- **1—6**：`abc`、空消息和 1/16/17/33 字节消息。
- **7—14**：15/31/32/47/48/49/256 字节及中文消息，使用非零密钥。

标签覆盖格式标识、版本、算法名、IV、密文长度和密文；本项目没有用户可传入的 AAD 字段。这些 JSON 全是正向回归用例，密文/IV/标签篡改、错误认证密钥等拒绝场景由单元测试覆盖。

## SM2 签名（16 例）

组级字段：`curve`、`userId`（身份的十六进制字节）和 `signatureFormat`。用例字段：`operation: verify`、`publicKey`、`msg`、`msgLen`、`signature`（DER 编码）和布尔值 `expected`。签名不直接保存为独立 `r`、`s` 字段。

- **1—2**：正常消息和空消息的有效签名。
- **3—6**：修改消息、修改签名、替换公钥、替换用户 ID，预期拒绝；第 6 例仍使用原公钥，只改变 ID。
- **7—13**：1/31/32/33/65/128 字节及中文消息的有效签名。
- **14**：自定义 ID 的有效签名。
- **15—16**：对新增有效签名修改消息或签名，预期拒绝。

## SM2 加密与格式（29 例）

`operation` 指定 `decrypt`、`encryptRoundTrip` 或 `convert`。解密使用 `privateKey`、`ciphertext`、`ciphertextFormat`、预期明文 `msg` 和布尔值 `expected`；回环还提供 `publicKey`。转换使用 `sourceFormat`、`targetFormat` 和 `expectedCiphertext`。

- **1—3**：固定密文解密、C1 篡改拒绝、32 字节消息随机加密回环。
- **4—5**：公开 IETF 草案附录的密文重排/DER 编码；附录使用不同示例曲线，只验证格式。
- **6—20**：1/31/32/33/128 字节消息在 C1C3C2、C1C2C3、DER 三种格式中的解密。
- **21—23**：C2 篡改、C3 篡改、错误私钥，预期拒绝。
- **24—29**：三种格式的全部六个相互转换方向；128 字节消息还检查 DER 长长度编码。

## 来源与运行

`sourceType`、`source` 记录来源；本轮新增用例以 `batch: boundary-2026-10` 标记。标准向量、推导向量和本地回归向量分开标记。本轮新增 96 例已用 OpenSSL 3.5.4 与 Python gmssl 3.2.2 交叉验证，不是新增官方标准向量。

```powershell
# 单个文件（文件路径是位置参数）
python runner.py vectors/sm4.json --backend cross

# 全部文件；如 PATH 中 OpenSSL 过旧，请指定 OpenSSL 3
python runner.py --all --backend cross --result-dir results --openssl "C:\Program Files\Git\usr\bin\openssl.exe"
```

测试密钥、私钥、IV 和固定随机数仅用于实验。复现脚本与扩充原因见 [向量扩充实验记录](vector-expansion.md)。
